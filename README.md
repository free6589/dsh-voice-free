# dsh-voice-free：给 DSH 网页版加个说话输入

对着麦克风说一段话，文字自己进输入框。识别不是插件做的，是你电脑上本来就有的 `f9-doubao` / `f9-metaso` 两个命令做的。插件只干三件事：接住浏览器录的音、存成一个 wav、把文字要回来。

## 这是个啥

DSH 网页版的输入框旁边会多一个麦克风按钮：点一下开始录，说完点「停止并识别」，文字回到输入框。你检查一遍，没问题再回车。

插件自己不做识别，它是换了个壳去调你已经在用的两个命令：

- `f9-doubao`：豆包，不用登录，默认主力
- `f9-metaso`：秘塔，要登录一次，备用

所以：

- 插件很轻：装完就几 MB，不占显卡，本机不跑任何计算，只负责把录音转手交出去。算声音的是两家的服务器，所以电脑差也不卡。
- 不碰你的 F9 / F10 键位绑定。插件调命令时加的是 `--no-inject`，只识别、绝不往你当前窗口打字。老习惯按 F9 说话，照样能用，两条路不打架。
- 你的账号、设备身份还留在原来的命令里，插件不读也不存。

## 装之前

1. 一台 Linux 电脑，DSH 网页版能正常打开。
2. 原来那两个命令是好的，跑一下：

   ```bash
   f9-doubao --selftest
   f9-metaso --selftest
   ```

   自检过了就说明没问题。还没装的话，先装 F9/F10 那套（f9-voice-input）。
3. 秘塔要登录过一次：在 f9-voice-input 目录里跑 `python3 login.py`，浏览器点确认。豆包不用登录。
4. 别和官方的语音输入包（voice-input-bundle）一起装。两边占同一组插件 id，会撞。

## 装

在插件目录里跑一条命令：

```bash
cd /home/fish/projects_mine/dsh-voice-free
dsh plugin --profile web add file:$PWD
```

`$PWD` 就是当前目录，所以必须先进到这个插件目录再执行。跑完不报错就行。

然后重启网页服务，三步：

1. 找到正在跑 `dsh web` 的那个终端，按 `Ctrl+C` 停掉；
2. 重新执行 `dsh web`；
3. 浏览器打开 `http://127.0.0.1:3080`，按 `F5` 刷新。

装好的样子：输入框旁边出现麦克风按钮（鼠标放上去写着「听写」）；打开 设置 → 插件，找到语音输入那一项（英文名 `@deepseek-ai/dsh-experimental-client-ui-voice-input`），它的配置页里「识别服务」下拉里能看到豆包和秘塔。

地址请用 `127.0.0.1`，别用局域网 IP，原因在下面「麦克风」那节。

## 用

1. 点麦克风。浏览器第一次会问能不能用麦克风，点允许。
2. 说话。说完点「停止并识别」。
3. 等一会儿，文字落在输入框里（顺利时两三秒，网络差会更久）。不满意可以点「丢弃识别文字」重录。
4. 看着没问题，回车发送。

一次最长录 2 分钟，到点会自己停。要说很久就分几段说。

「识别语言」保持「自动识别」或「中文」就行（就在同一个配置页里）。插件这边只认自动、中文、英语三种。

## 换主力

「主力」= 平时默认用哪个引擎。默认是豆包。

**换个默认引擎**：打开 设置 → 插件 → 语音输入那项的配置页，在「识别服务」下拉里选豆包或秘塔。选完就存进配置了，不用重启，以后默认用它。

**连自动兜底也一起换边**：默认只有豆包带兜底，豆包连不上会去找秘塔；反过来秘塔挂了不会回头找豆包。要让秘塔当主力、挂了落豆包，改插件目录下的 `cordis.patch.yml`：

```yaml
- id: voice-free
  name: ./host.mjs
  config:
    primary: metaso
```

改完重启 `dsh web`。

只改下拉、不改 `primary` 也能用，代价是你手选的那个引擎那一刻没有兜底。

## 麦克风

- 录音是在浏览器里做的，所以要浏览器点头。第一次弹窗选允许；以后想改，点地址栏左边那个小图标。
- **必须用 `http://127.0.0.1:3080` 打开。** 换成 `http://192.168.x.x:3080` 这种局域网地址，浏览器不让网页碰麦克风，只会提示「当前浏览器不支持录音」。
- 提示「麦克风不可用，请选择其他输入设备」：在刚才那个配置页里换一个「输入设备」。下面有「麦克风输入电平」，说话时那条在跳，就说明收得到音。
- 声音太小、环境太吵，会识别成空的。凑近点，一句话说完早点停。
- 提示「录音中断，请重试」：多半是耳机拔了、系统把设备切走了，重录一次就好。

## 断网、失败了怎么办

插件是按「先忍一下，再换一家」来设计的：

1. 豆包失败，等 3 秒重试，最多重试 3 次（加起来 4 次）；
2. 还不行，自动换秘塔，同样重试；
3. 两个都不行，输入框里统一写一句：**语音识别失败：网络好像有问题，录音已保存，网好了点重试**。

这句是「试过了、都没成」的总提示，不代表一定是断网。可能是断网，也可能命令没装好、秘塔登录过期。具体哪一步坏的，去 DSH 启动那个终端的日志里搜 `voice-free`：每一轮失败都写了引擎名、第几次、什么原因，全失败时还写了录音路径。

这时候录音没丢，存在系统临时目录 `dsh-voice-free` 里（Linux 一般是 `/tmp/dsh-voice-free/`，文件名是 `rec-日期-时间.wav` 的样子）。网回来以后有两种补救：

- 点「重新录音」重说一遍。网络恢复后不用重启 DSH。
- 或者手动补一刀，把最新的那条录音直接交给命令：

  ```bash
  ls -t /tmp/dsh-voice-free/
  f9-doubao --transcribe "$(ls -t /tmp/dsh-voice-free/*.wav | head -1)"
  ```

识别成功、或者你点了取消，临时录音会自动删掉，不会越攒越多。

常见提示对着看：

| 看到的提示 | 大概怎么回事 | 怎么办 |
| --- | --- | --- |
| 语音识别失败：网络好像有问题，录音已保存，网好了点重试 | 两个引擎都没成：断网、命令没装、登录过期，都可能 | 先跑下面那两条 `--selftest`；再确认秘塔登录没过期；都正常就查网络，还不行重启 `dsh web` 再试 |
| 未识别到语音 | 没出声，或者太小声 | 凑近重说，别一按就开始发呆 |
| 录音超过服务限制 | 一段录过 2 分钟了 | 分两段说 |
| 当前浏览器不支持录音 | 多半是拿局域网 IP 打开的 | 换成 `http://127.0.0.1:3080` |
| 麦克风权限未开启…… | 浏览器或系统把麦克风关了 | 地址栏左边允许麦克风，系统设置里也放开 |
| 点麦克风弹出「打开语音输入引导」 | 识别服务还没就绪（没装好，或者被禁用了） | 去 设置 → 插件 看语音输入那项；改完还是不行就重启 `dsh web` |

分不清是插件坏了还是命令坏了，就跑这两条：

```bash
f9-doubao --selftest
f9-metaso --selftest
```

自检过不去，问题在命令那边，把命令修好，插件不用动。

命令装在别处、不在 `~/.local/bin` 时，用环境变量把位置告诉插件：`DSH_VOICE_FREE_DOUBAO_BIN`、`DSH_VOICE_FREE_METASO_BIN`，写完重启 `dsh web`。秘塔登录过期就回 f9-voice-input 目录重跑 `python3 login.py`；豆包身份坏了跑 `f9-doubao --refresh-identity`。

## 卸

```bash
dsh plugin --profile web remove dsh-voice-free
```

然后重启 `dsh web`。原来的 F9 / F10 一点不受影响。

## 它不做什么

- 不改你的 F9 / F10 绑定，不往别的窗口打字。
- 不读、不存你的账号凭证，那些还在命令自己的配置里。
- 不替你按回车。识别出来的字先放输入框，发不发你说了算。
